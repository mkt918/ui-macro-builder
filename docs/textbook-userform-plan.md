# UI Macro Builder 大改修プラン — 教科書準拠「ユーザーフォーム＋VBA」対応

## Context（なぜやるか）

授業で使う教科書は、ユーザーフォーム（TextBox / Label / CommandButton）を設計し、
イベントプロシージャで処理してラベル等に出力する構成が中心。
扱う内容は次の順番で進む。
MsgBox → Sub → フォーム → 変数の型 → 計算 → 条件分岐 → 繰り返し →
ファイル入力（CSV）→ 配列 → 探索・並べ替え → 2次元配列。

いまのツールは次の前提で作られていて、教科書の大半を扱えない。
- 実行エンジンがブロックを直接たどる（`src/excel-preview.js` の `execBlock` / `evalValue`）
- 実行は「先に全部動かして、あとで再生する」方式
- `Sub MyMacro()` が1つだけ
- ループのカウンタは `i` 固定、配列は `arr` 1個だけ
- 次の機能が無い：フォーム、複数 Sub、型付き Dim、Select Case、And/Or/Not、ファイル入力

### 決定事項（ユーザー確認済み）

| 項目 | 決定 |
|---|---|
| 実行方式 | **コード基準**。VBA のテキストを直接解釈する実行エンジンを新しく作る。コードの直打ちは全項目で動く。ブロックは初級項目から順に対応し、未対応の構文はコード専用にする |
| フォーム設計 | **自由配置＋課題ごとの初期配置**。生徒が部品を配置・編集でき、課題側も配置済みのフォームを持てる |
| 課題 | **機能を先に作る**（自由制作モード）。課題は最後に教科書のページ順で作り直す |
| 対象者 | **プログラミングが初めての生徒**。中学1年生でも、説明を受けずに操作方法がわかることを目標にする（後述「初学者向けの設計方針」） |
| 作り方 | 実行エンジンと実行まわりの結線（app.js）は新しく作る。画面部品（コードエディタ・仮想Excel表示・ブロック定義・リファレンス・リサイズ）は流用する |
| 互換性 | 公開版は授業で未使用なので、旧版との互換は取らない。main で直接作業し、旧エンジンは新エンジンに置き換えたら削除する |
| 端末 | **Windows PC**（マウスとキーボード）。タッチ操作への対応は不要。画面幅はリサイズ機能で調整する |
| 本物の Excel | **使わない。このツールだけで完結する**。VBA の文法と動きは教科書どおりにする。ただし細部で迷ったら、正確さより分かりやすさを優先する。Excel へ移すための機能（.bas の書き出しなど）は作らない |
| 保存と提出 | **ファイル保存＋提出用リンク**。作品（コード・ブロック・フォーム・仮想ファイル・初期データ）を1つのファイルに保存・読み込みできるようにする（PC の再起動でブラウザのデータが消えても戻せる）。先生に送る共有リンクも用意する |
| ネットワーク | Blockly と CodeMirror を、CDN ではなくリポジトリに同梱する（学校のフィルタで止まらないように） |

## 全体アーキテクチャ

```
[ブロック] --generateVBA(+行→blockId対応表)--> [VBAテキスト] <--直打ち-- [コードエディタ]
                                                 │
                                  lexer → ast-parser → AST（行・列番号付き）
                                                 │
                       runtime（ジェネレータ関数 function* で書いた実行エンジン、DOM非依存）
                         ├ 状態が変わるたびに step を出す（差分＋一定間隔で全体保存）
                         └ MsgBox / InputBox / 入力待ちで一時停止 → 画面側が本物のダイアログを出して再開
                                                 │
                    Session（実行1回分の管理：区間・タイムライン・フォームの操作）
          ┌──────────────┬───────────────┬──────────────┬──────────────────┐
      📊仮想Excel    🪟ユーザーフォーム    📁ファイル    タイムライン／行・ブロックのハイライト
```

### 要点

- **新しいモジュール**：`src/vba/lexer.js`、`ast-parser.js`、`runtime.js`、`session.js`
  - DOM に依存しないので、ブラウザと Node の両方で読み込める
  - 書き出しは `if (typeof module !== "undefined") module.exports = …` とする
- **一時停止できるエンジン**：先に全部実行してから再生する方式はやめ、ジェネレータで少しずつ実行する
  - MsgBox と InputBox では本物の順番どおりに止まる。数当てゲームが成り立つ
  - 命令数の上限と時間の上限を設け、無限ループで画面が固まらないようにする。記録した step 数の上限とは別に数える
- **step の記録**
  - 記録するのは「状態が変わったとき」だけ。中身は差分にし、一定間隔で全体の状態を保存する
  - 理由：今のように毎回 JSON で丸ごと複製すると、ソートでメモリが足りなくなる
  - 各 step にはソースの行番号と blockId を持たせる
- **実行時エラーの扱い**
  - それまでの step は捨てない
  - `{steps, error:{line, msg}}` を返し、VBA と同じ日本語のエラー文を出す（例：「実行時エラー '6': オーバーフローしました。」）
- **コードが正になる場合**
  - コード→ブロック→再生成による手打ちコードの上書き（app.js:538）は無条件に止める
  - ブロックに変換できない構文を含むときは、ブロックタブに「このコードはブロックで表示できません（コードのまま実行されます）」と表示する
  - その状態でブロックを編集したら、上書きしてよいか確認する
- **編集中のプレビュー**
  - 入力が止まってから実行する（debounce）
  - 最初の InputBox やフォームの操作待ちに来たら「入力待ち」で止める
- **ハイライト**（今は無い機能。新しく作る）
  - CodeMirror では行をハイライトする
  - ブロックでは、Blockly の `STATEMENT_PREFIX`（`'@id …`）付きで生成し、その印の行を取り除きながら「行→blockId 対応表」を作ってハイライトする

## 教科書（第4章 手続き型言語のプログラミング p.90〜94）から読み取れたこと

| 教科書の内容 | このツールでの対応 |
|---|---|
| 基本の書き方は `Option Explicit` ＋ `Private Sub CommandButton1_Click()` で、Dim は手続きの中に書く。InputBox や MsgBox の例も、ボタンのクリックで動かす | 新規作成したときの初期状態を「UserForm1 ＋ CommandButton1 ＋ 空の `CommandButton1_Click`」にする。最初の1歩を「ボタンを押すと動く」にそろえる |
| 整数除算は `¥` と表記されている（日本語環境では `\` が `¥` に見える） | 字句解析で `\`・`¥`（U+00A5）・全角の `￥` のどれも整数除算として受け付ける。全角の `￥` は全角警告の対象にする |
| 演算子の優先順位は ①( ) ②^ ③* / ¥ Mod ④+ − で、同じ順位は左から計算する | **教科書の表に合わせる**（本物の VBA では * / → ¥ → Mod の順だが、本物の Excel は使わないため教科書を優先する） |
| 例は単精度型：A=7 のとき A/2=3.5、A¥2=3、A Mod 2=1、A^2=49 | この表をそのまま Node テストに入れる |
| `Val` は先頭から数字として読み、数字でない文字が出たらそこで止める。数字が1つもなければ 0 を返す。InputBox の戻り値は文字列 | この仕様どおりに実装し、テストする |
| `MsgBox ("金額は" & Kin & "円です")` のように、かっこ付きで書く | 文としての `MsgBox (式)` を受け付ける |
| 変数を「箱」の絵で説明している（Kin = Tanka × Suu で箱に 500 が入る） | 変数パネルを、教科書と同じ「名前の付いた箱」の見た目にする。代入されたら箱の中身が変わるアニメーションにする |
| 型は「整数型（Integer）」「文字列型（String）」「単精度浮動小数点数型（Single）」と日本語で呼ぶ | Dim ブロックと用語の説明に、日本語の型名を併記する |
| 変数名はローマ字（Tanka、Suu、Kin、Hinmei、Kotae） | ブロックで変数を作るときの例も、ローマ字の名前にする |
| すべての例題に**流れ図**がある（はじめ／おわりの端子、「100 → Tanka」の処理、「Suuを入力」の入出力の平行四辺形） | **「🔀 流れ図」タブを追加する**。プログラムから流れ図を自動で描き、実行中の箇所を光らせる（M2 で順次処理、M3 で分岐、M4 で繰り返し） |
| 実習問題 4-2-02 では、ラベルの BorderStyle・Font・ForeColor・TextAlign をプロパティウィンドウで設定している。ボタンは「日本語」「English」「終了」 | M1 のプロパティ欄で、Caption・Font（大きさ・太字）・ForeColor・BackColor・BorderStyle・TextAlign を編集できるようにする。フォームにはタイトル「UserForm1」と × ボタンを付ける |
| InputBox と MsgBox の画面は、Windows の標準ダイアログ（OK／キャンセル） | 同じ見た目のダイアログを作る。キャンセルしたときは `""` を返す |
| 例題（rei4-2-03）と実習問題（jis4-2-01）があり、それぞれ「入力データ・出力データ・処理条件・入力例・出力例」の構成になっている | M8 の課題を、この構成（例題と実習問題、5つの欄）で作る |
| **p.103〜108 条件判定（例題 4-3-01）**：`InputBox("重量を入力して下さい(g)", "重量入力", 0)` のように3つの引数（メッセージ・タイトル・初期値）を使う | InputBox の第2引数（ダイアログのタイトル）と第3引数（入力欄の初期値）に対応する（M2） |
| If の中で `End`（プログラムを終える）と `Exit Sub`（手続きを抜ける）を使い分けている | 両方に対応する。`End` はフォームを閉じ、実行を終える |
| `Label3.Caption = Omosa` のように、数値をそのまま Caption に入れる | 代入するときに文字列へ自動で変換する |
| ラベル3・4は SpecialEffect（へこんだ枠）で見た目を変えている | プロパティ欄に SpecialEffect（平面・へこみ・浮き出し）を加える |

| 比較演算子の表に、日本語の意味（等しい・等しくない・以上・以下・超える・未満）がある | 比較ブロックの選択肢を「>= （以上）」のように日本語の意味付きで表示する |
| **p.127〜131 ファイル（例題 4-3-06）**：`Open ThisWorkbook.Path & "¥uriage.csv" For Input As #1`、`Do While Not EOF(1)`、`Input #1, KouMei, Suu`、`Close #1` | M5 で対応する。パスに含まれる `¥` も区切りとして扱い、ファイル名だけで照合する |
| 名前に全角スペースが入っている（「高橋　礼」）。メモ帳の表示は「ANSI」（Shift_JIS） | 文字列データ内の全角スペースは、そのまま値として読む（全角警告はコードにだけ出す）。Shift_JIS での読み込みを必須にする |
| `Label1.Caption = Label1.Caption & KouMei & Chr(13) & Chr(10)` で、1つのラベルに複数行を表示する | Chr 関数と、改行（Chr(13) & Chr(10)、vbCrLf）を表示できる複数行ラベルに対応する |
| `Format(Kin, "###,##0")` で3けた区切りにする。Label2 は TextAlign を右寄せにする | Format の `#`・`0`・`,` の書式に対応する（M2）。TextAlign は右寄せにも対応する |
| Open の開き方には Input（読む）と Output（書く）がある | M5 では Input を中心にし、Output（`Print #`）にも対応して、書き出した中身を📁ファイルタブで見られるようにする |
| **p.141〜145 配列（例題 4-4-01）**：`Option Explicit` の次、Sub より前に `Dim Umei(5) As String` を書く（モジュールレベルの配列）。`UserForm_Initialize` で値を入れ、`CommandButton1_Click` で `Umei(Soe)` を読む | モジュールレベルの宣言と Initialize に対応する（M0・M1）。値は区間をまたいで保持する |
| 配列を「添字 0〜5 の箱が横に並んだ絵」で説明する（`Dim Umei(5)` では 0〜5 の6個ができ、0 は使わない） | 配列パネルを、`Umei(0)`〜`Umei(5)` の箱を横に並べた見た目にする。添字は箱の下、値は箱の上に書く。使っていない箱は薄く表示する（M6） |
| 流れ図は手続きごとに横に並べて描く（「UserForm_Initialize」と「CommandButton1_Click」） | 流れ図タブでは、手続きごとに見出しを付けて横に並べる |
| 教科書はコードと流れ図に ❶❷❸ の番号を付け、どこが対応しているかを示している | 流れ図の記号にマウスを乗せる・クリックすると、対応するコードの行が光るようにする（コードの行から流れ図の記号へも同じ） |

## 流れ図の描き方（教科書の書き方に合わせる）

| プログラム | 流れ図の記号 | 書き方の例 |
|---|---|---|
| 手続きの始まりと終わり、`End`、`Exit Sub` | 端子（角の丸い長方形） | 「はじめ」「おわり」。`End` と `Exit Sub` は、分岐の先に別の「おわり」を描く |
| 代入 `Kin = Tanka * Suu` | 処理（長方形） | 「Tanka × Suu → Kin」（`*` は ×、`/` は ÷ で書く） |
| TextBox から読む `Soe = Val(TextBox1.Text)` | 処理（長方形） | 「TextBox1 → Soe」（Val は書かない） |
| `UserForm_Initialize` の中の代入 | 準備（六角形） | 「"食料品" → Umei(1)」 |
| InputBox | 入出力（平行四辺形） | 「Suuを入力」 |
| MsgBox | 入出力（平行四辺形） | 「"重量オーバーです"を表示」 |
| Label の Caption に代入 | 入出力（平行四辺形） | 「OmosaをLabel3に表示」「""をLabel1に表示」 |
| `Input #` | 入出力（平行四辺形） | 「CSVファイルのデータをKouMei, Suuに読みこむ」 |
| If | 判断（ひし形）と YES / NO | 「Omosa ≧ 50」（`>=` は ≧、`<=` は ≦、`<>` は ≠ で書く）。手続きを終える側の分岐は横に出す |
| Do While / For | ループ端（上下の六角形） | 始端に「ループ1 データがある間」、終端に「ループ1」。`Not EOF(n)` は「データがある間」と書く |
| `Option Explicit`、`Dim`、`Open`、`Close` | 描かない | 教科書の流れ図にも出てこない |

## 初学者向けの設計方針（中学1年生でも使える）

すべてのマイルストーンに共通で適用する。新しい画面を作るたびに、この表で確認する。

| 方針 | 具体策 |
|---|---|
| **読める言葉** | 画面の文言は、中1が読める言葉にする。専門用語は、やさしい言い換えと用語を並べて書く（例：「ボタンを押したときの命令（イベントプロシージャ）」）。用語にマウスを乗せると説明が出る |
| **やることが1本道** | 画面の上に「① フォームを作る → ② 命令を組む → ③ ▶ 実行」の3ステップを表示し、いまどこにいるかを示す。▶実行ボタンは常に一番目立たせる |
| **少しずつ見せる** | ブロックのカテゴリは、学習の進み具合に合わせて増やす（最初は少なくする）。タイムラインの詳細や出発点などの上級者向け機能は「くわしく」に畳む |
| **はじめてガイド** | 初めて開いたとき、吹き出しで次の操作を1つずつ案内する。ボタンを置いて「こんにちは」を表示するまでを体験させる。あとから「使い方」でもう一度見られる |
| **エラーをやさしく** | VBA の本物のエラー文に加えて、①何が起きたか ②どこか（行・ブロックを光らせる）③どう直すか、をやさしい言葉で出す。例：「`x` という箱（変数）がまだ作られていません。`Dim x As Integer` を上に書こう」 |
| **全角・半角のつまずき対策** | 日本語入力のまま打った全角の記号・数字・スペース（＝ （ ） ” ， ０〜９ 全角スペース）を検出し、波線と「半角に直す」ボタンを出す。文字列 `" "` の中は対象外 |
| **フォームを簡単に作る** | 部品はクリックでも置ける（ドラッグしなくてよい）。グリッドに吸着させる。名前は自動で付ける。Delete で消せて、元に戻すもできる。部品を選ぶと「この部品でできること」を表示する |
| **大きく・押しやすく** | ボタンと文字は大きめにする。マウスが苦手な生徒やタッチ操作でも押しやすい大きさにする |
| **失敗しても大丈夫** | 自動保存、元に戻す、無限ループは自動で止めてやさしく知らせる。どの操作をしても作品が消えないことを優先する |
| **動きが見える** | 実行中の行・ブロック・セル・部品を光らせる。速さを🐢〜🐇で選べる |

検証：各マイルストーンの完了時に「初めて触る人チェックリスト」で確認する。
- 説明なしで、そのマイルストーンの基本操作ができるか
- エラーの文だけを見て直せるか
- 専門用語に、説明なしで出てくるものはないか

## マイルストーン（教科書の順に沿う。各段階で毎回動く状態を保つ）

### M0 実行エンジンの置き換え（見た目は変えない）
- lexer / ast-parser / runtime / session を作る
  - 構文の対象：今のブロックが生成するもの全部（Range / Cells / Rows、For、Do、If、MsgBox、InputBox、arr、WorksheetFunction.Round、Date など）
  - 複数の Sub、Dim と型の指定、モジュールレベルの変数、プロシージャのスコープも、ここで解析・実行できるようにする（型変換の細部は M2）
- **入れ子のカウンタ**
  - 生成するコードを、ループの深さに応じて `i / j / k` に分ける
  - `loop_index` と `{i}` は一番内側のカウンタを指すようにする（今は `this.i` の退避で隠しているだけ）
- **生成コードの修正**
  - どこにもつながっていない値ブロックは出力しない（scrubNakedValue）
  - 文字列中の `"` をエスケープする（vba-generator.js:205,276,292）
- **新エンジンへの切り替え**
  - 並行運用はせず、新エンジンに直接切り替える。旧 `Interpreter` / `buildSteps` は削除する
  - 計算の決まりは VBA どおりにする（0で割る・未定義の変数・型の不一致はエラー）。ただしエラーは「初学者向けの設計方針」のとおり、やさしい説明を付けて見せる
- **app.js 側**（実行まわりは継ぎはぎせず書き直す）
  - `hasExecutableProgram` を「状態が変わった step が1つ以上ある」に変える
  - 変数パネルは AST と実行時スコープから表示する
  - InputBox があるかの判定を AST 基準にし、キャッシュのキーは `行:列#回数` にする
- Node テストの土台を作る（`node --test tests/*.test.js`）
- 教科書の書き方への対応
  - 整数除算として `\` / `¥` / `￥` を受け付ける
  - 演算子の優先順位は教科書の表どおりにする：( ) → ^ → * / ¥ Mod（同じ順位は左から）→ + −
  - `MsgBox (式)`、`Option Explicit` を受け付ける
- 初学者向け：やさしいエラー表示（文法エラー・実行時エラー）、全角・半角の検出と「半角に直す」
- Blockly と CodeMirror を `vendor/` に同梱し、CDN への依存をなくす（**取り込みと index.html の切り替えは実施済み**）

### M1 ユーザーフォーム（教科書：フォーム・TextBox・CommandButton・End・イベントプロシージャ）
- 右ペインに「🪟ユーザーフォーム」タブを追加する（新ファイル `src/userform.js`）
  - **デザインモード**

    - デザイン画面は VBE と同じ点のグリッドにする。教科書の「画面設計」の図のように、部品の名前（Label1 など）を吹き出しで表示する切り替えを付ける
    - ラベルは複数行を表示できるようにし、縦長のラベルにも対応する（CSV の一覧表示で使う）
    - 部品をダブルクリックすると、コードに `Private Sub CommandButton1_Click()` の雛形が入る
    - 新しく作ったときの初期状態は「UserForm1 ＋ CommandButton1 ＋ 空の `CommandButton1_Click`（Option Explicit 付き）」にする
  - **ダイアログ**：InputBox（入力欄・OK・キャンセル）と MsgBox（OK）を、教科書に載っている Windows 標準ダイアログと同じ見た目で作る
  - **実行モード**

    - ボタンを押すたびに、そのイベントの区間をタイムラインに追加する（`append(segment)` を新しく作り、区間の始まりへ移動する）
    - TextBox への入力も「TextBox1 に入力」という step として記録する（巻き戻したときに表示を合わせるため）
    - 過去の時点を表示している間はフォームを操作できない。「最新へ戻る」で操作を再開する
    - 実行中にコードを編集したら、実行を終了してお知らせを出す
    - モジュールレベル変数は区間をまたいで保持する。Rnd のシードは実行ごとに固定する

### M2 変数と計算（型・Dim・&・InputBox・四則演算・\ Mod ^・Call・Format）
- **型**
  - Integer / Long / Single / Double / String / Variant
  - Integer の範囲を超えたらオーバーフローのエラーにする
  - 整数への代入と `\`・Mod は銀行型の丸めにする
  - `Dim a, b As Integer` では a が Variant になる（教科書でよく出る落とし穴）
  - Option Explicit、Const、Static
- **InputBox**：常に String を返す（Val の単元で「"1"&"2"="12"」を再現するため）。キャンセルしたら `""` を返す。第2引数（タイトル）と第3引数（初期値）に対応する
- **Chr / vbCrLf**：`Chr(13) & Chr(10)` でラベルを改行できるようにする
- **Format**：`"###,##0"` のような `#`・`0`・`,`・`.` の書式に対応する
- **Val**：教科書の説明どおり、先頭から数字として読み、数字でない文字が出たらそこで止める。数字が1つもなければ 0 を返す
- **変数パネルを「箱」にする**：教科書の絵と同じく、名前の付いた箱に値が入る見た目にする。型は日本語名で添える（整数型・文字列型・単精度浮動小数点数型など）
- **🔀 流れ図タブ（順次処理）**：AST から流れ図を自動で描く（新ファイル `src/flowchart.js`、SVG）
  - 記号：端子（はじめ／おわり）、処理（例「100 → Tanka」）、入出力の平行四辺形（例「Suuを入力」「"金額は" & Kin & "円です" を表示」）
  - 描き方は「流れ図の描き方」の表に従う。手続きごとに見出しを付けて横に並べる
  - 実行中の箇所を光らせる。記号とコードの行を、マウスを乗せる・クリックすることで対応させて光らせる
- **プロシージャ**
  - Call、Function、引数の ByVal / ByRef（既定は ByRef）
  - MsgBox の2・3番目の引数と戻り値
- **関数**：Format、Val、CInt / CLng / CDbl / CStr、Debug.Print
- **ブロック**：型を選べる Dim、`\` と `^`、Call、Format

### M3 条件分岐（If/ElseIf/Else・Exit Sub・Select Case・And/Or/Not・FizzBuzz）
- エンジン
  - If（ブロック形式と1行形式）
  - Select Case（`Is`、`To`、カンマ区切り）
  - And / Or / Not
  - Exit Sub / Exit Function
- ブロック
  - If に ElseIf を足せるようにする（mutator）
  - And / Or / Not、True / False
  - Select Case
- 流れ図：判断（ひし形）と Yes / No の分岐

### M4 繰り返し（For Next・二重ループ九九・Do While Loop）
- For のカウンタ名を自由にする（ブロックで変数を選べるようにする）
- `Do…Loop While/Until`（後判定）、Exit For / Exit Do、`:` と ` _`
- 流れ図：ループ端の記号（六角形の始端と終端）。For は始端に「i = 1, 9」のように書く

### M5 ファイル入力（Open For Input・Input #・EOF・Close・最大最小）
- 右ペインに「📁ファイル」タブを追加する
  - 仮想ファイル（名前と CSV の本文）を作る・直す
  - PC の CSV を読み込む
    - 文字コードは、まず UTF-8 として厳密に読み、失敗したら Shift_JIS で読む（TextDecoder）
    - Excel で保存した CSV にも対応するため
- 構文
  - `Open` はパスを無視してファイル名だけで照合する（`ThisWorkbook.Path & "\data.csv"` も通す）
  - `Input #`、`Line Input #`、`EOF`、`Close`、`FreeFile`
  - 引用符で囲まれた CSV の項目
  - ファイルが無いときはエラー53
- 部品に ListBox（`AddItem` / `Clear`）を追加する（CSV の一覧表示用。教科書は複数行ラベルで表示しているので、ListBox は補助）
- `Open … For Output` と `Print #` にも対応し、書き出したファイルを📁ファイルタブで見られるようにする
- 教科書の例題で使う `uriage.csv` を見本ファイルとして入れておく
- 保存：`umb_files`。サイズに上限を設ける（localStorage の容量対策）
- この段階はコード中心で進める。ブロックは後回し

### M6 配列・探索（Dim a(n)・集計・件数・線形探索・二分探索・数字あてゲーム・順位付け）
- 名前付き配列（`Dim a(10)`、`Dim a(1 To 10)`）、ReDim / ReDim Preserve、UBound / LBound
- Rnd / Randomize / Int
- 配列ビジュアライザ
  - 名前付き配列と LBound 基準に対応する（今は1から始まるため、添字0が表示されない）
  - 教科書の絵と同じく、`Umei(0)`〜`Umei(5)` の箱を横に並べる。添字は箱の下、値は箱の上に書き、使っていない箱は薄くする
  - 探索中の位置をハイライトする
- グリッドの上限（26行）を広げる（30人分の順位表を表示するため）

### M7 並べ替え・2次元配列
- 2次元配列 `Dim t(1 To 3, 1 To 4)`
- 配列ビジュアライザを2次元に対応させる
- 交換の様子をアニメーションで見せる
- 動作確認は、バブル・選択・挿入の3種のソートの模範コードで行う

### M8 課題を教科書順に作り直す

  - `scenario` は「入力 → 期待する出力」の組を並べた形にする（例題 4-3-01 の「22→84、25→84、40→94、65→重量オーバーです、0→終了」のように、クリック1回ごとに確認する）
- 教科書と同じ構成にする
  - 種類：**例題**（rei4-2-03 など。流れ図とプログラムを見ながら作る）と**実習問題**（jis4-2-01 など。自分で作る）
  - 欄：入力データ・出力データ・処理条件・入力例・出力例
- 教科書のページ順に課題を作る（ヒント3段階、模範コード、可能ならブロック）
- クエストの画面を再表示する

## 検証方法

- **Node テスト**（`node --test tests/`）。runtime を直接動かす
  - 単元ごとの模範コードを使う：MsgBox、型・オーバーフロー、Val、FizzBuzz、九九、CSV の最大・最小、線形探索・二分探索、数当てゲーム（InputBox の答えを台本どおりに渡す）、3種のソート、2次元配列
  - 最終状態（セル・ラベル・MsgBox の履歴・配列）とエラーの内容を確認する
  - 教科書 p.91〜94 の例をテストに入れる
    - 例題 4-2-03：InputBox に「5」と答える → MsgBox「金額は500円です」
    - 算術演算子の表：A=7（Single）→ 9 / 5 / 14 / 3.5 / 3 / 1 / 49
    - Val：`Val("12abc")=12`、`Val("abc")=0`
  - 教科書 p.103〜145 の例題をテストに入れる
    - 例題 4-3-01（重量）：22→84、25→84、40→94、65→「重量オーバーです」、0→終了
    - 例題 4-3-06（uriage.csv）：Label1 に11人の名前、Label2 に「8,000」〜「18,000」が改行区切りで入る
    - 例題 4-4-01（売場名）：Initialize のあと、TextBox1 に「1」を入れてクリック → Label1 が「食料品」
- **M0 の確認**：既存のブロックから生成したコードが新エンジンで動き、エラーが出ないこと
- **ブラウザ**：各マイルストーンの完了時に、コンソールにエラーが無いことだけを軽く確認する。プレビューの撮影はしない方針で、見た目はユーザーが確認する
- 各マイルストーンが終わるたびに commit と push を行う
